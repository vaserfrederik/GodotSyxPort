# Контрольная точка A64 — семантика тайлов мебели

A64 переносит из Java роли `FurnisherItemTile` для всех 659 извлечённых layouts. Каждая клетка
теперь отдельно описывает footprint, блокирование прохода и требование доступной кардинальной
стороны. Идентификатор `__` больше не считается пустой клеткой автоматически: пустотой является
только Java `null`.

## Что проверить в Godot 4 .NET

1. Открыть проект, дождаться сборки C# и начать новое поселение на карте 768×768.
2. Спланировать рабочую комнату с многоклеточной мебелью и вращать несколько вариантов.
3. Убедиться, что вариант с `mustBeReachable` нельзя подтвердить, если все четыре стороны
   соответствующей клетки закрыты блокирующими тайлами мебели.
4. Подтвердить допустимый вариант: материалы должны быть полностью доставлены до активации
   dormant furniture job, после чего один работник строит весь footprint атомарно.
5. Проверить, что работник может использовать неблокирующую клетку footprint как рабочую позицию,
   но не проходит сквозь блокирующую клетку готовой мебели.
6. Сохраниться во время строительства, загрузить save v29 и завершить объект. Затем отдельно
   загрузить существующий save v28 для проверки обратной совместимости.
7. Отменить незавершённый объект и разобрать готовую комнату: все клетки footprint, резервы и роли
   проходимости должны очищаться без повторного возврата ресурсов.

## Автоматическая проверка

`python3 Tools/verify_port.py` проверяет 659 layouts, допустимые символы ролей, четыре вращения,
контракты runtime и формат save v29. В текущем окружении проверка проходит; Godot/.NET SDK здесь
не установлены, поэтому сборка и игровой прогон остаются обязательным внешним этапом.
